* Files

| File                 | Content                                            |
|----------------------+----------------------------------------------------|
| =beamer-gui.el=      | the Emacs side: reading, measuring, writing code   |
| =beamer_gui.py=      | the editor window (PySide6)                        |
| =beamer_gui_core.py= | the editor's functions that need no Qt             |
| =quicktry.el=        | the =emacs -Q= sample                              |
| =publish.el=         | this site, from =docs/=                            |

The two sides exchange one JSON object per line.  The editor sends
saves and clicks on its standard output.  Emacs answers on its
standard input with the new session after each compilation, or with
an error.

* Tests

#+begin_src bash
make test        # Emacs (ERT), editor (pytest), layout
make lint        # checkdoc and package-lint
make fuzz        # random documents, edits and editor input; minutes
make docs        # this site, into html-content/
#+end_src

* Versions

#+begin_src bash
make set-version VERSION=0.2.1   # write it everywhere the current one is
make check-version               # the header is X.Y.Z
make check-version TAG=v0.2.1    # and matches the tag
#+end_src

The version is the =;; Version:= header of =beamer-gui.el=.  The
site's footer reads it.

The layout tests move each kind of element, twice, in top-aligned and
centred frames, and check that every other word of the slide stays
within 0.5pt.  The fuzzers keep failing cases in
=test/fuzz/fuzz-failures/=.

* Releases

A tag runs the lint, =make check-version= with the tag, the tests and
=make docs=, checks the site's links, and only then publishes the site
to GitHub Pages.
